# 2026 부안군 청년포럼 웹앱

「청년이 그리는 부안의 현재와 미래」 — 오프닝 스몰토크 · 청년정책 퀴즈 · 토크콘서트 · 원탁토론
네 세션을 한 웹앱으로 진행합니다. 화면은 두 개 — 진행자용(빔프로젝터), 참여자용(QR로 접속하는 휴대폰).

빌드 과정이 없는 순수 HTML/CSS/JS이고, 데이터는 Firebase(Firestore + Storage)에, 페이지는
GitHub Pages에 올려 씁니다. **주소가 고정**이라 QR을 행사 전에 미리 인쇄해 테이블에 깔아둘 수 있고,
진행자 노트북이 도중에 꺼지거나 와이파이가 끊겨도 참여자 휴대폰과 데이터는 그대로 살아 있습니다.

파일을 고치려는 분은 이 문서 대신 **[MAP.md](MAP.md)** 를 먼저 보세요 — "뭘 바꾸려면 어디를 여는지" 표 하나로 끝납니다.

---

## 처음 배포하기 (한 번만)

### 1. Firebase 프로젝트 만들기
1. [console.firebase.google.com](https://console.firebase.google.com) → 프로젝트 추가
2. 프로젝트 안에서 **Firestore Database** 생성(프로덕션 모드로) + **Storage** 생성
3. **Authentication** → Sign-in method → **익명(Anonymous)** 사용 설정
4. 프로젝트 설정(⚙️) → 내 앱 → `</>` 웹 앱 추가 → 이름 아무거나 → "구성" 탭에 뜨는
   `firebaseConfig` 객체를 복사

### 2. 이 저장소에 연결
1. [js/firebase.js](js/firebase.js)를 열어 `firebaseConfig`를 방금 복사한 값으로 교체
2. Firestore 콘솔 ▸ 규칙 탭에 [firebase/firestore.rules](firebase/firestore.rules) 내용을 붙여넣고 **게시**
3. Storage 콘솔 ▸ 규칙 탭에 [firebase/storage.rules](firebase/storage.rules) 내용을 붙여넣고 **게시**
4. Firestore 콘솔에서 문서 하나를 손으로 만듭니다 — 이게 **진행자 키**입니다:
   - 컬렉션 `forums` → 문서 ID `buan2026`(= [content/forum.json](content/forum.json)의 `id`와 반드시 같아야 함)
   - 그 안에 컬렉션 `config` → 문서 ID `host` → 필드 `key`(문자열) = 아무 진행자 키(예: `bg2026`)
   - 진행자 화면은 이제부터 `host.html?k=bg2026` 로 열어야 조작할 수 있습니다

### 3. GitHub Pages에 올리기
1. GitHub에 새 저장소 만들고 이 폴더 전체를 업로드(커밋)
2. 저장소 Settings ▸ Pages ▸ Branch를 `main`(또는 쓰는 브랜치)으로 지정 → 저장
3. 1~2분 뒤 `https://<계정>.github.io/<저장소이름>/` 이 참여자 주소, 그 뒤에 `host.html?k=<진행자키>`를 붙이면 진행자 주소

### 4. QR 인쇄
참여자 주소를 QR로 만들어 미리 인쇄해도 됩니다 — 주소가 고정이라 행사 당일 바뀌지 않습니다.
(진행자 화면 대기화면에도 같은 QR이 실시간으로 뜹니다.)

## 로컬에서 미리 확인하기

이 프로젝트는 `<script type="module">`을 쓰기 때문에 `file://`로 직접 열면 브라우저가 막습니다.
아무 로컬 서버로 열어야 합니다. 예:

```bash
npx serve .
```

또는

```bash
python -m http.server 8080
```

띄운 뒤 `http://localhost:포트/host.html?k=<진행자키>` 와 `http://localhost:포트/` 를 각각 브라우저 두 창으로 열어 확인합니다.

## 화면 레이아웃(해설이 잘리는지 등) 점검하기

Firebase 연결을 마친 뒤, 진행자 화면을 열고 개발자 도구 콘솔에 [tools/stage.js](tools/stage.js)를
붙여넣으면 실제로 문제를 누르지 않고도 특정 문항의 정답 공개·데이터 화면·최종 순위 화면을
바로 강제로 띄울 수 있습니다. 해설이 긴 문항일수록 꼭 한 번씩 확인하세요.

## 행사 당일 진행

1. 노트북에서 `host.html?k=<진행자키>` 를 열고 빔프로젝터에 띄웁니다
2. 하단 탭바로 언제든 세션 1~4를 자유롭게 오갈 수 있습니다(순서를 벗어나도 됩니다)
3. **2. 청년정책 퀴즈** — 큰 버튼 하나가 상황에 맞게 문구가 바뀝니다(퀴즈 시작 → 정답 공개 → [⭐문항만] 데이터 보기 → 다음 문제 → 최종 순위). `Space`로도 같은 버튼이 눌립니다. `←/→`로 문항을 자유롭게 오갈 수 있습니다
4. **4. 원탁토론** — 「발표모드로」를 누르면 참여자 휴대폰에 사진 업로드·하트 버튼이 나타납니다
5. `F` 전체화면(무대모드) · `H` 조작바 숨김/보이기

## 사고 대비

- **노트북이 꺼지거나 와이파이가 끊겨도** 참여자 휴대폰과 지금까지의 답변·사진·하트는 Firebase에 그대로 남아 있습니다. 노트북을 다시 켜서 같은 주소(`host.html?k=...`)를 열면 진행 상황이 그대로 이어집니다. **주소도 안 바뀝니다** — 참여자가 QR을 다시 찍을 필요가 없습니다.
- **참여자 휴대폰 화면이 꺼지거나 새로고침돼도** 조 번호는 기억되고(브라우저 저장), 답변·업로드한 사진도 그대로 남아 있습니다.
- **문제를 잘못 띄웠으면** 「이 문제 답 초기화」로 그 문제만 다시 받을 수 있습니다.
- **전체 초기화**(퀴즈: 답변·점수·접속 조 목록 / 원탁토론: 사진·하트)는 리허설 뒤 실전 전에 한 번씩 눌러 깨끗하게 시작하세요. 되돌릴 수 없습니다.
- 진행자 키(`?k=`)를 모르면 아무도 진행자 화면을 조작할 수 없습니다.

## 알아두어야 할 한계 (일부러 간단하게 만든 부분)

- **로그인이 없습니다.** "이 팀이 정말 3번 테이블 사람인가"는 검증하지 않습니다(참가자가 자기 조 번호를 직접 고릅니다). 진행자 조작만 `?k=` 키로 막혀 있습니다. 같은 행사장 안에서만 쓰는 도구라 이 정도로 충분하다고 보고 설계했습니다.
- **전체 초기화는 업로드된 사진 파일 자체(Storage)는 지우지 않고, 화면에서 보이는 목록만 지웁니다.** 저장 용량이 걱정될 정도로 사진이 쌓이지 않는 규모(하룻밤 6~12장)라 문제 없지만, 완전히 지우려면 Firebase 콘솔의 Storage에서 직접 지우면 됩니다.
- **하트 투표는 기기(브라우저) 기준입니다.** 같은 사람이 사파리와 크롬을 번갈아 쓰면 두 번 투표한 것처럼 잡힙니다.
