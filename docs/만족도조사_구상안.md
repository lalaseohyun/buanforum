## 1. 설문 문항 — 검토 의견 포함

### Q1. 척도형 ⚠️ 수정 제안

**원안**: 매우 만족한다 / 다소 유익했다 / 잘 모르겠다 / 그저 그랬다

이 보기는 그대로 쓰면 **분석할 때 곤란해집니다.** 세 가지 문제가 있어요.

1. **척도가 섞였습니다** — "만족한다"와 "유익했다"는 다른 차원이에요. 만족도를 물어놓고 유익도로 답하게 하면 결과 해석이 안 됩니다.
2. **부정 응답 선택지가 없습니다** — "잘 모르겠다"와 "그저 그랬다"는 둘 다 중립이에요. 불만족한 사람이 고를 칸이 없으면 만족도가 인위적으로 높게 나오고, 보고서 신뢰도가 떨어집니다.
3. **간격이 불균등합니다** — 매우만족(+2) / 다소유익(+1) / 잘모르겠다(0) / 그저그랬다(0). 평균 점수를 낼 수 없어요.

**수정안 (5점 척도)**

> 오늘 청년포럼 진행에 전반적으로 만족하셨나요?
> ① 매우 만족 ② 만족 ③ 보통 ④ 불만족 ⑤ 매우 불만족

- 5점 척도면 **평균 만족도(예: 4.3점)** 라는 대표 숫자가 나옵니다. 보고서 첫 페이지에 쓸 수 있어요.
- 긍정응답률(①+②)도 계산 가능 — "만족도 87.5%" 같은 표현이 여기서 나옵니다.
- 표준적인 척도라 내년 포럼과 비교도 됩니다.

4점 척도를 원하시면 `매우 만족 / 만족 / 불만족 / 매우 불만족`(중립 제거)이 대안이에요. 어느 쪽이든 **부정 선택지는 꼭 넣으시길** 권합니다.

### Q2. 복수선택 (2개까지)

> 가장 만족스러웠던 프로그램은? (2가지 선택)
> □ 오프닝 스몰토크 □ 청년정책 퀴즈 □ 토크콘서트 □ 정책발굴(원탁토론)

- UI에서 **2개 초과 선택 시 차단** + "2개까지 선택할 수 있어요" 안내
- 분석 시 주의: 응답자 수 ≠ 응답 수. 보고서에는 **"응답자 대비 선택률"** 로 표기해야 합니다. (40명이 2개씩 = 80응답 → 퀴즈 30표면 30/80이 아니라 30/40 = 75%)

### Q3. 주관식 ⭐ 실시간 송출

> 특히 기억에 남는 점, 유익했던 점이 있다면 1~2가지 적어 주세요.

### Q4. 척도 + 주관식 ⚠️ 수정 제안

**원안**: 일정과 시간 구성, 적절했나요? (주관식)

주관식만 받으면 그래프를 못 만듭니다. **척도 + 이유** 조합을 권해요.

> 포럼 일정과 시간 구성은 어떠셨나요?
> ① 너무 길었다 ② 적절했다 ③ 너무 짧았다
> └ 그렇게 생각하신 이유가 있다면? (선택 입력)

이러면 막대그래프 하나가 나오고, 주관식은 근거로 인용할 수 있습니다. 특히 "너무 길었다"가 많으면 내년 큐시트를 줄이는 명확한 근거가 돼요. 포럼이 18:30~21:20으로 2시간 50분이라, 이 문항은 실제로 유용한 데이터가 될 가능성이 높습니다.

### Q5. 주관식 ⭐ 실시간 송출

> 기타 하고 싶은 말, 제안하고 싶은 의견을 자유롭게 적어 주세요.

## 3. 실시간 오픈엔디드 화면 ⭐ 핵심

### 레이아웃 — 2분할

```
┌─────────────────────┬─────────────────────┐
│  기억에 남는 것       │  하고 싶은 말        │
│  ─────────────      │  ─────────────      │
│                     │                     │
│  ┌───────────────┐  │  ┌───────────────┐  │
│  │ 퀴즈에서 부안   │  │  │ 내년에도 꼭    │  │
│  │ 청년이 6천명    │  │  │ 열어주세요     │  │
│  │ 밖에 안 된다는  │  │  └───────────────┘  │
│  │ 게 충격이었다   │  │  ┌───────────────┐  │
│  └───────────────┘  │  │ 시간이 조금    │  │
│  ┌───────────────┐  │  │ 길었어요       │  │
│  │ 원탁토론에서    │  │  └───────────────┘  │
│  │ 다른 팀 정책이  │  │                     │
│  │ 좋았다         │  │                     │
│  └───────────────┘  │                     │
│              23개    │              19개    │
└─────────────────────┴─────────────────────┘
```

- 좌우 각각 독립적으로 동작 (한쪽이 비어도 다른 쪽은 정상 작동)
- 하단에 각 문항 응답 수 표시
- 세로 구분선은 옅은 진회색 또는 골드 20%

### 움직임 방식 제안 — 하이브리드 방식 추천

세 가지 안을 검토했는데, **C안(하이브리드)** 을 권합니다.

**A안. 세로 스크롤 (티커식)**
카드들이 아래에서 위로 천천히 흐르고, 끝에 닿으면 다시 순환.
- 장점: 구현 단순, 모든 의견이 반드시 한 번씩 노출됨
- 단점: 새로 들어온 응답이 언제 나올지 모름. 방금 쓴 사람이 자기 글을 못 볼 수 있음

**B안. 랜덤 부유 (버블 플로트)**
카드가 화면 안에서 천천히 떠다니며 위치가 계속 바뀜.
- 장점: 시각적으로 화려함
- 단점: **읽기 어렵습니다.** 움직이는 텍스트는 눈이 따라가기 힘들고, 카드끼리 겹치면 가려짐. 빔프로젝터에서는 특히 취약해요

**C안. 하이브리드 ⭐ 추천**

```
[새 응답 도착]
      ↓
① 하이라이트 — 화면 중앙에 크게 3초간 단독 표시
      ↓
② 합류 — 축소되면서 상단으로 슬라이드 인
      ↓
③ 순환 — 4초마다 한 칸씩 위로 이동, 화면 밖으로 나가면 대기열 뒤로
      ↓
④ 대기열 소진 시 셔플 후 재순환 (같은 순서 반복 방지)
```

- **①이 핵심입니다.** 방금 응답한 사람이 "내 의견이 화면에 떴다"를 확실히 경험하게 되고, 이게 다른 참가자의 추가 응답을 부릅니다. 멘티미터가 잘하는 지점이기도 해요.
- ③의 4초는 조절 가능하게 두시고, 실제 리허설 때 읽히는 속도로 맞추세요.
- ④의 셔플이 "골고루 보이게"를 담당합니다. 단순 순환은 순서가 고정돼서 뒤쪽 응답이 계속 뒤에 남아요.

### 세부 규칙

| 항목 | 규칙 |
|---|---|
| 응답 5개 미만 | 움직이지 않고 그냥 배치 (스크롤하면 허전해 보임) |
| 카드 표시 개수 | 한 열에 3~4개 (빔프로젝터 가독성 기준) |
| 긴 텍스트 | 70자에서 자르고 `…` 처리, 전체는 엑셀에 저장 |
| 빈 응답 | 저장은 하되 화면에는 미표시 |
| 등장 효과 | fade-in + slide-up 400ms (튀는 효과는 피하기) |
| 폰트 크기 | 최소 24px 이상 (뒷자리에서도 읽혀야 함) |

### ⚠️ 진행자 숨김 기능 — 꼭 넣으세요

실시간으로 화면에 송출되는 구조라, **부적절한 응답이 그대로 뜰 위험**이 있습니다. 공식 행사이고 군수·의원이 참석하는 자리라 더 그래요.

- 진행자 화면(별도 URL 또는 단축키)에서 응답 목록을 보고 **개별 숨김 토글**
- 숨긴 응답도 데이터에는 남김 (엑셀에는 포함, `표시여부` 컬럼으로 구분)
- 최소한 **전체 일시정지 단축키**라도 넣어두시면 급할 때 화면을 멈출 수 있습니다

구현 시간이 없으면 일시정지만이라도 꼭 넣으세요.

- 응답률은 반드시 밝히세요. 30% 응답률과 80% 응답률은 해석이 완전히 다릅니다.

### 요약 (1페이지)
- 평균 만족도 O.O점 / 긍정응답률 OO%
- 가장 만족스러웠던 프로그램 1위
- 핵심 제안 3가지

### 문항별 분석

| 문항 | 그래프 | 비고 |
|---|---|---|
| Q1 만족도 | 가로 막대 (5점 척도 분포) + 평균 점수 큰 숫자 | 100% 스택 바도 가능 |

- 각 유형별 응답 수 + 대표 인용 2~3개
- 원문 전체는 부록에

- 이 부분이 사실상 보고서의 목적입니다. 앞의 그래프는 근거고요.

## 6. 앱 내 배치

하단 탭을 `홈 / 1 / 2 / 3 / 4 / 5`로 늘리거나, 5번은 탭에 넣지 않고 **4번 원탁토론 끝에서 이어지는 화면**으로 두는 두 가지 방법이 있어요.

**추천: 탭에 넣기 (홈/1/2/3/4/5)**
진행 중 언제든 QR 화면으로 돌아가야 할 수 있고(늦게 온 사람, 다시 QR 보여달라는 요청), 마무리 시간에 오픈엔디드 화면과 QR 화면을 오가야 하기 때문입니다.

**5번 세션 내부 화면 구성**

```
5-1. QR 코드 화면 (응답 받기)
      ↓ 진행자가 넘김
5-2. 실시간 오픈엔디드 2분할 화면
      ↓ (진행자 전용)
5-3. 진행자 관리 화면 — 숨김 토글 + 엑셀 다운로드
```

5-3은 참가자에게 보이면 안 되니, 별도 URL(`/admin` 등)이나 단축키(예: `Ctrl+Shift+A`)로 여세요.

## 7. Claude Code에 전달할 문구

> 웹앱 마지막에 만족도조사 세션(5번)을 추가해줘. `docs/만족도조사_구상안.md` 참고.
>
> - 하단 탭을 홈/1/2/3/4/5로 확장
> - 5-1: QR 코드 전체화면 + 실시간 응답 수 카운터
> - 5-2: 실시간 오픈엔디드 2분할 화면 (좌: Q3, 우: Q5)
>   - 새 응답 도착 시 중앙에 3초 하이라이트 → 축소되며 목록 합류
>   - 4초마다 한 칸씩 위로 이동, 대기열 소진되면 셔플 후 재순환
>   - 응답 5개 미만이면 움직이지 않고 배치
>   - 70자 초과 시 말줄임
> - 5-3: 진행자 관리 화면 (`/admin`) — 응답별 숨김 토글, 전체 일시정지, 엑셀 다운로드(SheetJS)
> - 설문 폼은 별도 라우트(`/survey`)로, 모바일 전용. 익명 안내 문구 넣어줘
> - Firebase Realtime DB 경로는 `/survey/responses/`
> - 문항은 구상안 1번 항목의 **수정안** 기준으로 (Q1은 5점 척도, Q4는 척도+주관식)
>
> 기존 브랜드 스타일 그대로 따라가줘.
