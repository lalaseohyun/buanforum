# 참여자용 페이지 구상 — 검토 및 제안

> 2026 부안군 청년포럼 · 참여자 전용 허브 페이지
> 기존 진행자용 웹앱과 분리된 별도 진입점

---

## 결론부터

**방향은 맞습니다.** QR을 세션마다 다시 띄우는 방식은 실제 현장에서 잘 안 돌아가요. 늦게 온 사람, 화면 놓친 사람, 폰 껐다 켠 사람이 매번 생기고 그때마다 진행이 끊깁니다. **QR 하나로 밤새 쓰는 허브**가 훨씬 낫습니다.

다만 지금 구상 그대로 만들면 **네 개가 동시에 다 열려 있다는 문제**가 생깁니다. 이것만 해결하면 좋은 설계예요.

---

## 1. 가장 큰 문제 — 시간 통제가 없음

포럼은 순차적으로 진행되는데, 허브는 네 칸이 처음부터 다 활성화돼 있습니다.

- 19시에 누군가 **만족도조사**를 눌러서 제출해버림 → 아무것도 안 겪고 낸 응답이 데이터에 섞임
- 퀴즈 진행 중에 **대표정책 제안**을 눌러 사진 올림 → 아직 토론도 안 했는데 빈 종이 사진이 화면에 뜸
- 반대로 원탁토론 시간에 **퀴즈**를 눌러 점수를 흔듦

### 해결: 진행자가 켜고 끄는 상태 제어

Firebase에 현재 활성 세션 값을 두고, 참여자 허브가 이걸 실시간으로 읽습니다.

```
/forum/activeSession: "quiz"   // 진행자 화면에서 변경
```

타일 상태는 세 가지:

| 상태 | 표시 | 동작 |
|---|---|---|
| **진행 중** | 골드 테두리 + 살짝 확대 | 탭 가능 |
| **곧 열립니다** | 흐리게(40%) + 자물쇠 | 탭 불가, 안내 토스트 |
| **완료** | 체크 표시 | 탭 가능(조회만) |

이렇게 하면 부수 효과가 하나 생깁니다. **허브 자체가 진행 상황판이 돼요.** 참여자가 자기 폰만 봐도 "지금 뭐 하는 시간이고, 다음은 뭔지"를 압니다. 화면 안 보이는 뒷자리 사람에게 특히 좋습니다.

**예외: 시행계획 타일은 항상 열어두세요.** 나머지 셋은 행동(참여·제출·응답)이지만 이건 읽기 자료라 언제 봐도 무해하고, 오히려 대기 시간에 미리 훑어보면 원탁토론이 깊어집니다.

**만족도조사는 포럼 종료 후에도 계속 열어두세요.** 현장에서 못 낸 사람이 집에 가서 내는 경우가 꽤 있습니다.

## 2. "조별 대표자 1명만" — 글씨로는 안 지켜집니다

작은 글씨 안내만으로는 한 조에서 두세 명이 들어옵니다. 기존 퀴즈가 팀 코드 방식이니, 같은 코드로 두 번째 기기가 들어왔을 때 어떻게 할지 정해두셔야 해요.

**추천: 확인 단계 한 번 넣기**

```
┌────────────────────────────┐
│  3조 대표로 참여합니다        │
│                            │
│  우리 조에서 한 명만 참여해요  │
│  이미 다른 분이 하고 있다면    │
│  뒤로 가주세요               │
│                            │
│  [ 3조 대표로 시작하기 ]      │
└────────────────────────────┘
```

여기에 더해, 이미 접속 중인 팀이면 **"3조는 이미 참여 중입니다"** 를 띄우고 계속할지 물어보는 정도면 충분합니다. 완전 차단은 위험해요 — 대표자 폰 배터리가 나가면 교체를 못 하게 되니까요.

## 3. 대표정책 제안 타일 — 안에 두 단계가 있습니다

이 타일 하나에 성격이 다른 두 행동이 들어갑니다.

1. **제출 단계** (20:00~20:40) — 종이에 쓴 정책양식 사진 촬영·업로드
2. **투표 단계** (20:40~21:00) — 다른 팀 정책 보고 공감 투표

같은 타일을 눌렀는데 시점에 따라 다른 화면이 나와야 해요. `activeSession` 값을 `proposal_submit` / `proposal_vote`로 나누면 됩니다.

투표 단계에서는 **자기 팀 정책에 투표 못 하게** 막아두시고요. 팀 코드를 알고 있으니 어렵지 않습니다.

---

## 4. 시행계획 타일 — 모바일 구조

진행자용은 화살표로 넘기는 5페이지 구조인데, 참여자 폰에서 그대로 쓰면 답답합니다. 손가락으로 좌우 스와이프하면서 표를 읽는 건 불편해요.

**추천 구조**

```
[허브] → [분야 목록 5줄] → [분야별 사업 표] → (뒤로)
```

```
┌────────────────────────────┐
│ ← 2026 청년정책 시행계획      │
│   49개 사업 · 117억 6,882만  │
├────────────────────────────┤
│ 주거          15개  62.5억 › │
│ 교육           3개  22.0억 › │
│ 일자리        13개  20.6억 › │
│ 복지문화      11개  11.3억 › │
│ 참여권리       7개   1.3억 › │
└────────────────────────────┘
```

- 분야 목록을 먼저 보여주면 **전체 구조가 한 화면에 잡힙니다**
- 하나 탭하면 그 분야 사업 표 (세로 스크롤, 카드형)
- 표 안에서는 좌우 스와이프로 인접 분야 이동 가능하게 하면 편해요
- 상단 back 버튼 상시 노출 (깊이가 3단계라 필수)

> 말씀하신 "원탁토론의 3페이지"가 제가 아는 참고자료 화면(49개 사업)을 뜻하는 걸로 이해했습니다. 다른 화면을 말씀하신 거면 알려주세요.

## 5. 라우팅 — 참여자가 루트를 가져가야 합니다

QR을 못 찍고 **주소를 직접 타이핑하는 사람이 반드시 나옵니다.** 그러니 짧고 외우기 쉬운 쪽을 참여자에게 주세요.

| 대상 | 경로 | 비고 |
|---|---|---|
| 참여자 | `/` (루트) | QR + 구두 안내용 짧은 주소 |
| 진행자 | `/host` | 빔프로젝터 송출 화면 |
| 관리자 | `/admin` | 숨김 토글, 엑셀 다운로드 |

`/host`와 `/admin`은 검색엔진에 안 걸리게 `noindex` 넣어두시고요.

**QR 배치**: 화면에만 띄우지 마시고 **테이블 텐트에 인쇄해서 각 조 테이블에 올려두세요.** 이게 현장에서 가장 확실합니다. 화면 QR은 진행자 화면 구석에 작게 상시 노출해두면 좋고요.

---

## 6. 세션 유지

참여자가 폰을 껐다 켜거나 브라우저를 닫아도 팀 정보가 유지돼야 합니다. `localStorage`에 팀 코드와 닉네임(있다면)을 저장하고, 재접속 시 자동 복원하세요. 만족도조사 제출 여부도 저장해서 중복 제출을 막으시면 좋습니다.

```js
localStorage: {
  teamCode: "3",
  surveyDone: true
}
```

## 7. 최종 허브 화면안

```
┌──────────────────────────────────┐
│  2026 부안군 청년포럼               │
│  청년이 그리는 부안의 현재와 미래     │
├─────────────────┬────────────────┤
│ ✓ 청년정책 퀴즈  │  2026 부안군    │
│                 │  청년정책       │
│ 조별 대표자      │  시행계획       │
│ 1명만 클릭       │                │
│                 │  49개 사업      │
├─────────────────┼────────────────┤
│ ● 대표정책       │ 🔒 청년포럼     │
│    제안         │    만족도조사    │
│                 │                │
│ 우리 그룹이      │  오늘          │
│ 제안하는 정책    │  어떠셨나요?    │
└─────────────────┴────────────────┘
      ● 진행 중   ✓ 완료   🔒 대기
```

- 상단 제목·부제는 말씀하신 대로
- 각 타일에 상태 아이콘 (● 진행 중 / ✓ 완료 / 🔒 대기)
- 하단에 범례 한 줄
- 진행자용 홈과 같은 2×2 격자라 시각적으로 이어집니다

**타일 순서**: 지금 순서(퀴즈 → 시행계획 → 대표정책 → 만족도)가 시간 흐름과 맞아서 그대로 두시면 됩니다. 시행계획만 성격이 다르지만, 퀴즈 직후에 자연스럽게 보게 되는 위치라 오히려 적절해요.

## 8. Claude Code 전달 문구

> 참여자 전용 페이지를 추가해줘. `docs/참여자용페이지_구상안.md` 참고.
>
> **라우팅 재구성**
> - `/` → 참여자 허브 (신규)
> - `/host` → 기존 진행자용 웹앱 전체 이동
> - `/admin` → 관리자 화면
>
> **참여자 허브 (`/`)**
> - 상단: "2026 부안군 청년포럼" + 부제 "청년이 그리는 부안의 현재와 미래"
> - 2×2 타일: ① 청년정책 퀴즈(조별 대표자 1명만 클릭) ② 2026 부안군 청년정책 시행계획(49개 사업) ③ 대표정책 제안(우리 그룹이 제안하는 정책) ④ 청년포럼 만족도조사(오늘 어떠셨나요?)
> - Firebase `/forum/activeSession` 값을 실시간 구독해서 타일 상태 제어
>   - 진행 중: 골드 테두리, 탭 가능 / 대기: 40% 흐림 + 자물쇠, 탭 불가 / 완료: 체크, 조회만
>   - **시행계획 타일은 항상 활성**, 만족도조사는 포럼 종료 후에도 활성 유지
>
> **진행자 화면에 세션 전환 컨트롤 추가**
> - `activeSession` 값을 바꾸는 버튼: `waiting / quiz / proposal_submit / proposal_vote / survey / ended`
>
> **각 타일 진입 화면**
> - 퀴즈: 팀 코드 입력 후 "N조 대표로 시작하기" 확인 단계 추가. 이미 접속 중인 팀이면 경고 후 계속 여부 확인
> - 시행계획: 분야 목록 5줄 → 탭하면 해당 분야 사업 표(세로 스크롤 카드형), 좌우 스와이프로 분야 이동, 상단 back 상시 노출
> - 대표정책: `activeSession`이 `proposal_submit`이면 사진 업로드 화면, `proposal_vote`면 투표 화면. 자기 팀 정책엔 투표 불가
> - 만족도조사: 기존 설문 폼
>
> **세션 유지**: localStorage에 teamCode, surveyDone 저장하고 재접속 시 복원
>
> 모바일 전용으로 만들고, 기존 브랜드 스타일 그대로 따라가줘.
